# 数据约定

## 现成缓存

`--data-root`指向包含下列文件的目录，可以是已有缓存本身，无需将它复制到代码仓库：

| 文件 | 含义 |
|---|---|
| radar_u8.npy | `(N,66,70)`，已反转解码的uint8：0=0dBZ、255=50dBZ |
| pwv_u8.npy | 同形状，0=0mm、255=80mm |
| times.npy | 严格递增、无重复的N个datetime64时间标签 |
| R1_train.npy / R2_train.npy | 对应方向的窗口起始索引 |
| R1_valid.npy / R2_valid.npy | 完整验证窗口索引 |
| R1_screen.npy / R2_screen.npy | 固定验证筛选窗口；必须属于完整验证 |
| R1_test.npy / R2_test.npy | 历史测试窗口索引 |
| manifest.json | 至少提供dataset_id；原缓存还包含文件哈希 |

注意：**原始PNG白色为0，黑色为物理上限；缓存已经反转一次。读取缓存时不能再反转。** 存储器使用只读内存映射，按批次搬到设备，不预先把全部数据装进GPU。

起始索引i对应历史i…i+9，未来i+10…i+29；起报是times[i+9]。连续30帧必须全在所属划分中，间隔均为6分钟。缺帧形成的间断会使该窗口无效，不补帧、不把整点RAIN作为本任务标签。

## 从PNG构建

CSV列为`time,radar_path,pwv_path`。相对路径相对CSV所在目录解析；也接受绝对路径。每行必须是同一时间的配对原始灰度图。示例仅展示格式，实际训练需要覆盖相应训练/验证月份。

构建器要求原图PIL模式L、尺寸70×66，采用`255−灰度`制作uint8缓存，不做灰度重映射、尺寸缩放或时间插值。遇到缺文件、重复时间或错误格式会报错。

新缓存按相同月份边界划分，验证筛选为最多768个均匀位置窗口；**它不等于历史冻结的筛选索引**。重放历史结果应使用历史缓存及其原始索引、dataset_id和固定种子。

## 标准化与实时性

仅从训练窗口所覆盖的唯一未来雷达帧拟合均值/标准差，随权重保存；验证和测试不参与拟合。残差扩散用同一训练雷达标准差缩放残差，冻结底座不更新。

数据处理来源、时区与PWV上游实时可用延迟仍需核实。代码仅取过去标签不证明上游产品从未使用未来观测。不得把该缓存协议直接当作业务实时因果性验证。
